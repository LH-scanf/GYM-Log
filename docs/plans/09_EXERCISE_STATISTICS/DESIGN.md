## 1. 目标与阶段边界

动作页承担动作发现与管理；动作详情承担该动作的训练表现；统计首页只回答总体训练频率与时长。按 09A、09B、09C 顺序分别实现、测试、提交和验收。09A 保持现有“点动作进入编辑”的行为，09B 才切换为详情页；09C 等详情及旧链接兼容完成后再移除统计首页的动作入口，任何阶段都不出现无路可达的动作统计。

## 4. 动作详情与趋势口径

顶部显示名称、`category` 对应身体部位、由 `RecordSchema` / `LoadMode` 生成的记录方式、归档状态（若有）与编辑入口。无记录时显示明确空状态，动作信息和编辑入口仍可用。

普通 `EXTERNAL` 且启用 load + reps 的力量动作：概览显示累计有效记录组数、最大有效训练重量及该重量对应次数、最佳估算 1RM。有效重量需为正且具有合法次数；同一最高重量出现多次时取最大次数，仍同值时取最近日期。1RM 沿用 Epley `load × (1 + reps / 30)`，只在此类动作呈现。其他类型以相应指标代替不适用项，不伪造 1RM：`BODYWEIGHT_PLUS` 为最大额外负重与次数；`ASSISTANCE` 为最小辅助重量及对应次数，并提示下降通常表示进步；纯次数为最佳次数；有氧按启用字段优先时长，并可用距离、速度、坡度。可选字段缺数据时展示“—”或空状态，不把缺失当作 0。

详情底部只有一张趋势图。普通外部负重动作提供“重量 / 估算 1RM”，默认“月 + 重量”；其他动作只提供语义成立且有启用字段的指标，不显示不可用的 1RM 切换。周为以本地今天为结束日的最近 7 个日历日，月为最近 30 个日历日；全部涵盖完整历史。周/月按训练日期聚合为每日一个点，重量取当日最大有效训练重量，1RM 取当日最大有效估算值；同日多场训练合并。全部按跨度决定粒度：跨度不超过 90 天按日，91–365 天按自然周，超过 365 天按自然月，每桶取对应指标的有效最值，点上展示周期日期范围。辅助重量的每桶数值取最小值，其他指标按其语义选最大值或总量并在图例写明。无记录日期不补零、不连出虚假采样点；横坐标按真实日期/周期位置排列，避免稀疏记录被画成等间距训练；点的日期/区间和数值可触摸、可键盘访问，手机触点不少于 44px，趋势图兼容 320–430px 与 reduced motion。聚合、筛选和最大重量对应次数均在 Domain/Application 层完成，React 不计算第二套统计。

## 5. 历史兼容与约束

- 统计按 `exerciseId` 查询，改名、归档后历史仍归原动作；历史记录原值不改写。
- 旧数据 `category` 缺失继续走现有幂等补全，用户手动分类不被覆盖；不升级 IndexedDB schema version。
- 旧统计 URL 保留明确跳转；旧 `/exercises/:id` 书签在 09B 后进入详情，编辑通过新地址进入。
- 统计页移除入口之前先保证动作列表、归档视图和旧 URL 均可达详情。
- 不新增依赖、不持久化派生统计、不重设计全站。
